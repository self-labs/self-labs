# Self-Labs, landing page

Institutional landing page for Self-Labs, published on the apex of `selflabs.org`.
This file is the single source of truth for anyone, human or agent, working in this repo.

## What this is

A static, bilingual, single-page site presenting Gustavo Cateim's engineering
portfolio: twenty projects, five engineering principles drawn from the code
itself, and four proof numbers pulled live from the GitHub API.

Two routes only: `/` (Portuguese) and `/en/` (English). Same page, same section
order, different locale.

## Stack

| Layer      | Choice                              | Why                                                                 |
| ---------- | ----------------------------------- | ------------------------------------------------------------------- |
| Framework  | Astro 7, `output: 'static'`         | Ships zero JS by default. No runtime, no server.                    |
| Content    | Content Collections + Zod           | Adding a project is a JSON file, never a layout edit.               |
| i18n       | Astro native i18n                   | `/` is pt, `/en` is en. No automatic redirect by `Accept-Language`. |
| Fonts      | `@fontsource-variable/*`            | Self-hosted WOFF2. No runtime CDN, ever.                            |
| Hosting    | Cloudflare Workers Static Assets    | Worker with no `main`: it only serves files.                        |
| Versioning | CalVer `YYYY.M.R` in `package.json` | Shown in the footer.                                                |

### If `npm run dev` dies with EPERM

The symptom is `EPERM: operation not permitted, rmdir 'node_modules\.vite\deps'`,
followed by `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)` from libuv.

Every directory in this checkout carries the Windows ReadOnly attribute. Measured:
345 of 345 under `node_modules`, 11 of 11 under `src`, and the repo root itself.
Node's `rmdir` returns EPERM on a ReadOnly directory, and Vite deletes and
recreates `.vite/deps` on every re-optimisation, so the dev server dies there.

Clearing the attribute by hand only works until the directory is recreated. The
fix in `astro.config.mjs` writes the Vite cache outside the project instead, under
`%LOCALAPPDATA%\vite-cache\self-labs`, and only on Windows: CI keeps the default.
Verified by running `astro dev --force`, which wipes and rebuilds the whole cache,
the exact operation that used to fail.

## Writing rules, non negotiable

These are enforced by `npm test`, which runs in CI before every deploy.

1. **Never mention BRFarma**, pharmacies, drugstores or medication. The owner
   removed that project from scope. `tests/conteudo.test.mjs` fails the build if
   the words reappear anywhere under `src/` or `scripts/`.
2. **No em dash (—) and no en dash (–)**, in any language, anywhere: copy, code
   comments, commit messages, PR bodies. Use a comma, a colon, parentheses, or a
   new sentence.
3. Portuguese with complete and correct diacritics. English that reads native,
   not translated.
4. No agency jargon. No emoji in page content.
5. Every claim must trace to something real in a repository. No invented numbers.

## The four proof numbers are derived, never typed

- `commits` and `repositorios`: `scripts/fetch-stats.mjs` against the GitHub API,
  counting PRIVATE repositories too. Public-only undercounted badly and silently:
  the `self-labs` org alone holds nine private repos, and the real figure went
  from 501 commits across 13 repos to 1397 across 28, of which 14 are private.
  A repo only counts once it has at least one commit authored by the owner, which
  is what keeps untouched forks out of the total.
- `prsExternos`: same script, via the search API.
- systems in production: counted from the project files that have a
  `selflabs.org` link and a production status. It cannot drift from the showcase.
- months of operation: computed from the oldest public repository to build date.

`.github/workflows/stats.yml` re-reads them every Monday and commits only when a
value actually changed, and that commit triggers the deploy workflow.

It only triggers it because the checkout step authenticates with `STATS_TOKEN`.
Actions fires no workflow for an event created with the default `GITHUB_TOKEN`,
which is the infinite-loop guard, and the side effect here was silent and severe:
the bot committed fresh numbers, no deploy ran, and the live site kept serving the
old ones until somebody pushed by hand. Measured on 2026-08-24, commit ca46e52
updated the file and triggered nothing.

**The scheduled run needs `STATS_TOKEN`.** The `GITHUB_TOKEN` Actions injects is
an installation token scoped to this repository only, so it cannot see private
repos in the other accounts: with it the count collapses to whatever is public.
`STATS_TOKEN` must be a classic PAT with the `repo` scope. Without it nothing
breaks, the coherence guard refuses to write a big drop over a good number, so the
figures simply freeze at the last good value instead of shrinking on their own.

If the API fails, `fetch-stats.mjs` keeps the committed file and exits 0. A stale
number on the page beats a build broken at three in the morning by a 502.

## Design decisions worth knowing before changing CSS

- **Dark only, on purpose.** The five brand trace colours sit between 1.45:1 and
  1.58:1 against white, so they are unusable as text on a light background.
- **`body` uses `overflow-x: clip`, not `hidden`.** `hidden` turns the body into a
  scroll container, which silently kills `scroll-behavior: smooth` on `html` and
  makes every anchor jump. This already happened once.
- **Anchor navigation uses NATIVE smooth scrolling**, driven from `Trilha.astro`.
  An earlier version animated frame by frame with `requestAnimationFrame` and had
  a defect that only shows on a real device: rAF is throttled when the tab loses
  focus, when the phone enters battery saving, or under load. Measured here in a
  throttled environment it dropped to 1 frame per second, turning a 900ms
  animation into two jumps. Native scrolling runs on the compositor and does not
  suffer from that. The JavaScript remains only for what CSS cannot do: subtract
  the header height explicitly, suspend snapping during the trip, and update the
  URL without the browser jumping.
- **Narrow screens get a `<dialog>` menu**, in `MenuMobile.astro`. Never declare
  `display` on that dialog: a closed `<dialog>` is `display: none` by browser
  rule, and overriding it leaves the panel visible on screen permanently. This
  already happened once. What hides above 48rem is the trigger button.
- **Body copy is justified from 48rem up, never below it.** On a phone the
  reading column is around 21rem, too few words per line, and the word spacing
  reads visibly uneven from one paragraph to the next. Narrow screens keep plain
  start alignment. Where justification does apply, `hyphens: auto` comes with it
  and is not optional, otherwise the column fills with rivers of whitespace.
  Hyphenation only works because `<html lang>` carries the right language.
- **`--folga-ancora` is the single source** for the sticky header offset. CSS and
  the navigation script both read it. Changing it in one place is enough.
- **Scroll snap is `proximity`, never `mandatory`.** With `mandatory`, the
  twenty card grid would trap a reader in its first screen.
- **The rail's wire measures the vias, not the window.** `Trilha.astro` wraps the
  `<svg>` and the `<ol>` in `.trilha-nucleo` for exactly this. Loose inside the
  fixed `.trilha`, the wire inherited the viewport height and ran edge to edge
  while the rings occupied ~216px in the middle, reading as a line belonging to
  nothing. Note the wire needs an explicit `height`: an `<svg>` is a replaced
  element, so pinning both `inset-block` ends does NOT stretch it, it falls back
  to the viewBox's intrinsic 100px and stops mid rail.
- Centre things geometrically (`display: grid; place-content: center`) rather
  than with `50% + translate(-50%)`, which lands on half pixels inside bordered
  boxes.

## The ECG, read this before touching `Hero.astro`

One defect came back three times here, always reaching the owner as the same
sentence: "the dot disappears before reaching the end". The three causes were
different every time, and all three came from the same shape of mistake, so the
current design removes the shape rather than patching the symptom.

- **The trace is still and the head sweeps over it.** An earlier version scrolled
  the trace _and_ ran the dot, so what you saw was the difference between the two
  speeds. That difference could only ever be a whole multiple of 120 units, and a
  window is any width at all, so on a 1920px monitor the dot died at 79% of the
  band, in fully opaque area, and reappeared on the left out of nowhere.
- **The two axes are separate nested groups.** The inner one repeats a single
  cycle of the wave forever, the outer one is a straight line. Phase can no
  longer drift, because the sweep lasts a whole multiple of the wave by
  construction: `calc(var(--ciclos) * var(--batida))`.
- **`--batida` is the only free number.** It sets the heart rate and everything
  else derives from it. Reduced motion changes that one value and both axes slow
  down together, which is what the old per animation durations kept getting wrong.
- **The band lives inside a `.casca`.** Loose in the section it spanned the whole
  window while every other block stopped at 74rem, and its top border read as a
  rule belonging to nothing. Containing it also caps the width at 1080px, which is
  what makes the coverage maths finite.
- **The scale is 1.375, not 1.4.** The band declares `height: 3.5rem` and carries
  a 1px top border under `border-box`, so the content area is 55px over the 40
  viewBox units. Getting this wrong by 0.025 silently approves breakpoints that
  come up short on screen.
- **The mask ends at `--fim`, never at a fixed percentage.** This is the fix for
  the fourth return of the bug. With a fixed 78% cut the dot reached 91.7% of the
  band but started fading at 78, and the trace stayed visible past it: there was a
  end of line the head could never reach. Tying the fade to `--fim` makes the
  trace stop where the dot stops, so "did it vanish early?" stops being a question.
- **`--fim` is derived, never typed.** A cycle is 120 viewBox units over the 40 the
  band shows, so it is exactly three times the content height. Measured in Chrome
  with Windows at 125%, a 1px border computes to 0.8px and the scale moves from
  1.375 to 1.380: a `--fim` hardcoded at 165px per cycle is 3.6px off on a 1080px
  band and drifts further with every zoom step.
- **The fade is symmetric.** It was 2.5rem in and 3.5rem out, and the difference
  showed: the dot was born fast and died slow, which reached the owner as "starts
  well, finishes badly".
- **Reduced motion keeps the pulse, at half the pace, and it takes JavaScript.**
  Chromium zeroes the duration of every CSS-declared animation while the
  preference is on, but the Web Animations API is not cut: measured, a 4000ms
  JS animation kept its full duration and advanced 135px in 900ms. So a small
  script re-drives the ECG through `.animate()` at half cadence, reading the
  keyframes straight out of the stylesheet so the wave geometry never lives in
  two places. The travel is unchanged; only the rhythm halves. That is a
  defensible trade: the preference exists for wide displacement, parallax and
  zoom, not for a 2.4px dot crossing a footer slowly.
- **The CSS still parks the band, and that parking is the no-JavaScript path.** Chromium forces
  `animation-duration` to `1e-06s` on every CSS animation while the preference is
  on, so any duration declared inside that media query is discarded before it can
  matter. Measured on the owner's Chrome and reproduced with the preference
  emulated. The band used to freeze on frame one with the head at x=0, inside the
  edge the mask erases, which reads as broken. It now rests one whole cycle in:
  on the baseline, because the wave only returns to it every 120 units, and at
  21% of the band, clear of both fades. One cycle and not two, because the
  narrowest band only travels two.
- **Every var in the animation shorthand carries a fallback.** A var that fails to
  reach the element invalidates the entire declaration, and the symptom is not a
  wrong duration: the animation stops existing, silently.
- **The glow trail is a mask that shares the head's animation.** The trace is drawn
  twice, once dim and always visible, once bright and clipped by a moving gradient.
  Give the trail its own animation and the glow lights up where the head is not.

`tests/animacao.test.mjs` reads the breakpoints, the mask and the height straight
out of the component and recomputes the coverage for every width band. It reads
the fade percentage from the mask itself rather than repeating it, because a
number written in two files is a number that will diverge.

## Security headers, and what must never reach a public log

This repository is PUBLIC, and that fact drives everything in this section.

### The headers are generated, never written by hand

`scripts/build-headers.mjs` runs last in the build and writes `dist/_headers`,
which Workers Static Assets parses and applies to every asset response. It works
without a worker script; the moment somebody adds a `main` with
`run_worker_first`, responses produced by that script stop carrying these
headers, with no warning and no deploy error.

The CSP does not use `unsafe-inline`. It lists the sha256 of every inline
`<script>` and `<style>` in the built pages, because `inlineStylesheets:
"always"` puts all the CSS inline and every behaviour script is inline too.
Those hashes change on any build that touches CSS or JS, which is exactly why
the file is derived: a stale CSP does not loosen, it BREAKS the page, silently,
and only in the visitor's browser.

Three findings came out of serving the policy over http and loading it in a real
browser, and none of them would have been caught by reading it:

- Comments in this project mention the `<style>` tag inside the prose. The
  extraction started inside a comment and ended at the real `</style>`, hashing
  a mix of comment and CSS. The `@keyframes` block ended up with no hash and the
  animation died.
- `font-src 'self'` refused two families, because Astro embeds part of the woff2
  as data URIs inside the inline CSS. The page fell back to system fonts with no
  sign on this side.
- A generic `style-src` with hashes made Chrome refuse the 36 `style=""`
  attributes citing `style-src`, not `style-src-attr`. Declaring
  `style-src-elem` and `style-src-attr`, and no generic `style-src`, fixes it.

`tests/cabecalhos.test.mjs` locks all three, plus the rule that every inline
block in `dist` has a matching hash.

### `no-transform` on the HTML routes is a CSP fix, not a cache decision

A fourth finding, and this one only showed up by hashing the HTML the live site
serves rather than the HTML the build produced.

The zone runs Bot Fight Mode, and on the free plan that turns on Cloudflare's
JavaScript Detections with no way to disable only that. JSD injects an inline
script into every HTML response AFTER the Worker has replied, so its hash cannot
exist when `_headers` is generated. Measured in production on both routes:
eleven inline blocks, one of them with no hash, and a `Refused to execute inline
script` in every visitor's console. The site itself was never affected, because
the seven project scripts all carry hashes.

A hash cannot fix it: the snippet carries the ray id and a timestamp, so it
changes on every request. Cloudflare recommends a nonce, and that is where the
circularity bites: a nonce needs a fresh value per response, which needs a
Worker, and building a `Response` in the Worker to insert it makes the response
"generated by your Worker code", which is exactly the case where `_headers` stops
applying. The fix would delete what it fixes. Snippets would work but need a paid
plan, and Transform Rules have no random generator, so a nonce derived from the
ray id is predictable, which is `unsafe-inline` with extra steps.

`Cache-Control: no-transform` on the HTML routes is the documented condition
that stops the injection, and it fits inside the file that already exists.
`js_detection.passed` goes from `false` to `missing`, which changes nothing here
because no WAF rule reads it. The routes are derived from `dist` by `rotaDe()`,
never typed, because a third route would silently ship without the header and
the failure would only appear in a visitor's console.

**HSTS covers the apex only**, deliberately: no `includeSubDomains`, no
`preload`. This zone carries dozens of subdomains pointing at homelab and VPS
tunnels, and `includeSubDomains` would order every browser that visits the page
to demand valid HTTPS on all of them, for a year, from the first visit.

Two more traps worth knowing: a `_headers` outside the root of `dist` is not
read and gets published as a fetchable asset instead, and an `.assetsignore`
listing `_headers` (a common copy paste from Pages migration guides) kills the
file silently. Neither exists here, and neither should.

### Never print a private repository name

`fetch-stats.mjs` runs weekly with a token that sees everything. It used to log
one line per repository including the private ones, and since Actions logs on a
public repository are readable by anyone without logging in, that published the
full inventory: private repository names with exact commit counts, fourteen of
them in a measured run, three of which appear nowhere on the site.

The page only ever needed the sum. Names of private repositories are masked
unless `SELFLABS_VERBOSE=1`, which the CI never sets. Fixing the script does not
erase logs already published: those have to be deleted by hand in the Actions
interface.

The same rule applies to anything added here later. Aggregate in public, keep
the detail behind an env var that only exists on the owner's machine.

## Brand assets

`src/assets/brand/selflabs-source.svg` is the raw CorelDRAW export and the only
hand authored file. Everything else is generated by `npm run brand`.

The source carries a background rect and a viewBox that does not start at the
origin (roughly `4313 1775 8723 11231`). Any script reusing those paths inside a
new viewBox must subtract `minX`/`minY` first, otherwise the drawing lands
outside the frame. `build-og.mjs` has an `encaixar()` helper for exactly this.

Palette, sampled from the artwork: `#20292E` petrol, `#0BE4EB` cyan, `#10E8D2`,
`#2CEBCE`, `#3AF2A8` mint, `#4BED9B` green.

## Deploy

Push to `master` → GitHub Actions runs `check`, `test`, `build` → `wrangler
deploy` publishes the Worker → a curl check confirms the apex returns 200.

Required repository secrets: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`.

The `selflabs.org` zone already carries 38 subdomains pointing at homelab and VPS
tunnels. This site takes the apex and `www`, and touches nothing else.

## Contact channels

Both live in `src/i18n/contato.ts`, kept apart from `ui.ts` because they are data,
not copy: they change value without changing language.

- Email `contato@selflabs.org`, routed through Cloudflare Email Routing on the zone.
- WhatsApp, a personal number, which is why its button carries secondary weight
  while email stays the primary channel.

If `WHATSAPP` is ever emptied, the button disappears instead of rendering a broken
link. Keep that behaviour: a wrong phone link sends visitors to a stranger.

There is deliberately no contact form. A form would need an endpoint, would store
what people write, would attract spam, and would produce the same email the link
already produces. It would be the only part of the site contradicting the section
next to it.
